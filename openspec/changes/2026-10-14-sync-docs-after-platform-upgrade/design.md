# Design

## Context

这是升级系列中唯一一个纯文档变更，也是唯一一个**必须最后执行**的变更。

它的风险与前几个变更相反：前几个变更是「改了代码但可能没更新文档」，本变更是「更新文档时可能记录下错误的事实」。具体来说——如果在本系列中途执行，文档会记录下随后又被改掉的中间状态（例如 Boot 3.5 而非 4.1、Gradle 8.14 而非 9.x、JDK 21 而非 25），产生二次返工。

因此本变更 SHALL 在前 5 个升级变更全部归档后执行。

另有一条前置依赖：`docs/standards/` 目录在当前 checkout 中**不存在**（`AGENTS.md` §规范体系表引用了 `docs/standards/architecture.md`、`code-style.md`、`testing.md`、`cds.md` 四份基线文档）。执行本变更时需先确认这些文件的实际存在状态：

- 若存在 → 直接更新
- 若不存在（与 `openspec/` 目录同类的缺失） → 在 tasks 中记录该缺失，并把「补建基线文档」作为独立后续事项，SHALL NOT 在本变更中凭空重写四份基线文档的内容

## Goals / Non-Goals

**Goals:**

- `AGENTS.md` 中不再有任何与代码不符的版本号、架构决策或命令
- 性能类文档中的数字全部来自实测，SHALL NOT 沿用旧版本
- 文档中引用到的每个能力 / 文件路径都能被检索到

**Non-Goals:**

- 不重写四份基线文档的结构与组织方式
- 不删除 AGENTS.md 中「后续演进思考」章节的待办项（它们是路线图，不是事实陈述）
- 不补充本次升级之外的新内容（如 CI 接入、安全加固的详细方案）

## Decisions

### 决策 1：区分「事实陈述」与「路线图」，只改前者

`AGENTS.md` §11「后续演进思考」中的条目（如「密码存储当前为 MD5，应升级为 BCrypt」「JWT 走 URL query 参数应迁移到 Header」）是**待办而非现状描述**。本变更 SHALL NOT 删除或改写这些条目——它们记录的是演进方向，即使方向已被采纳为 spec（`openspec/specs/auth-account` 已把 MD5、URL token 等记录为基线行为），路线图本身仍然有效。

**判据**：一句话的主语若是「系统现在是什么」→ 需核对更新；若是「系统应该变成什么」→ 保留。

### 决策 2：性能数字必须替换而非增补

`docs/standards/cds.md` 的「Metaspace 下降 78%、wall-clock 加速约 17%」是 Java 21 下的测量值。本变更 SHALL **删除**这些数字并写入 Java 25 下的实测值，SHALL NOT 以「Java 21 时曾达 78%」的形式保留——保留会诱导后来者引用过期结论作为基线判断。

同时 SHALL 记录测量方法（采样次数、硬件环境、JVM 参数），否则数字不可复现也不可证伪。

### 决策 3：架构决策表的删除与新增要成对

`docs/standards/architecture.md` §5.6「关键架构决策（不可破坏）」表中：

| 操作 | 条目 |
|------|------|
| 删除 | 「双数据源」——uid 数据源随百度 UID 组件一并移除 |
| 新增 | 「统一工具链语言级别」——三个模块的 Java 语言级别由 toolchain 统一声明，不可能漂移 |
| 保留 | 「可插拔模板引擎」「外部 Git 模板仓库」「虚拟线程异步」——均不受本系列影响 |

新增条目不是「顺手记录」，而是回答「为什么三个 build.gradle 的 Java 版本不会不一致」这个此前无答案的问题。

### 决策 4：废弃端点清单与 `api-deprecation-policy` 对齐

`README.md` §四 记载废弃端点清单，`AGENTS.md` §8 要求删除端点时同步更新该清单。本变更 SHALL 检查两者的一致性，并把 `api-deprecation-policy` 中新增的「前端静态产物调用计入核查范围」要求写入 README 对应章节——否则后续按 README 办事的人仍会漏检前端调用。

## Risks / Trade-offs

| 风险 | 影响 | 缓解 |
|------|------|------|
| `docs/standards/` 四份基线文档实际不存在 | 本变更的核心目标（更新基线文档）无法执行 | tasks 中设前置检查步骤；缺失时记录为独立后续事项，SHALL NOT 凭空重写 |
| 文档更新滞后于代码 | 后续会话仍读到过时信息 | 把「文档中的每个版本号都能在构建文件中检索到」列为逐条验收项 |
| 把「双数据源」从架构决策表删除后，未来又需要多数据源 | 决策表缺少先例 | 本次删除有明确依赖分析支撑（见 `2026-10-14-replace-baidu-uid-generator/design.md` 决策 6）；未来若重新引入，SHALL 走新的变更提案 |
| 性能数字在文档中随环境漂移 | 数字失去参考价值 | 同时记录测量方法与硬件环境，使数字可被复现与挑战 |
| 误删 §11 的路线图条目 | 丢失演进信息 | 决策 1 的判据；tasks 中逐条列出 SHALL NOT 改动的章节 |
